# KPI Catalog

A KPI is only useful if it helps someone make a decision.

Every metric in this catalog is tied to one of the seven decisions in the [Decision Catalog](1.3%20Decision_Catalog.md), has a named owner from the [Stakeholder Matrix](1.2%20Stakeholder_Matrix.md), and is defined precisely enough that two people calculating it from the same data get the same number.

The catalog is also the contract for the data model: every KPI lists the source fields it needs, so the star schema can be designed to calculate all of them.

---

# How To Read This Catalog

Each KPI includes:

| Field | Meaning |
|---|---|
| **ID** | Stable identifier used in the data model, Power BI measures, and AI agent outputs |
| **Definition** | What the KPI tells the business, in plain language |
| **Formula** | Exact calculation |
| **Grain** | The lowest level at which the KPI is calculated (it can always be rolled up) |
| **Source** | Tables and fields used, from `03_Source_Data` |
| **Direction** | Whether higher or lower is better |
| **Baseline** | Value from the platform's data for Oct 2025 – Sep 2026 |
| **Target / Thresholds** | Green / Amber / Red ranges |
| **Owner** | Stakeholder accountable for the KPI |
| **Decision** | Decision(s) from the Decision Catalog the KPI supports |

---

# Calculation Conventions

These rules apply to every KPI unless the KPI says otherwise.

1. **Reporting period.** KPIs are calculated monthly and on a trailing 12 months (T12M) basis. Point-in-time KPIs (inventory value, days of supply) use the last day of the period.
2. **Date basis.** Demand and sales use the order date. Purchase orders use the PO date for counts and the receipt date for delivery performance. Inventory uses the transaction timestamp.
3. **Stocked part.** A part is *stocked* at a branch if it has an inventory record (opening balance or any transaction) at that branch. Fill rate and stockout KPIs only apply to stocked parts.
4. **Costing.** Inventory and cost of goods are valued at the unit cost on the transaction. Current on-hand is valued at current part master cost.
5. **Data quality.** KPIs are calculated on records that pass all **High** severity data quality rules. Records that fail are excluded and counted in the data quality KPIs, never silently dropped.
6. **Duplicates.** Duplicates are resolved before calculation using the business key (for example, sales order + line).
7. **Currency.** All values are in USD.

# Customer Service KPIs

These KPIs measure whether customers get their parts when they need them. For a dealer, parts availability directly drives repeat business and machine uptime.

## SVC-01 Line Fill Rate

| | |
|---|---|
| **Definition** | Percentage of order lines filled completely from stock at the time of the order. Also called *first-pass fill rate*; the industry's primary parts service metric. |
| **Formula** | Count of demand lines where `qty_filled_from_stock = qty_demanded` ÷ count of demand lines |
| **Grain** | Demand line (branch × part × day) |
| **Source** | `demand_transactions`: `qty_demanded`, `qty_filled_from_stock` |
| **Direction** | Higher is better |
| **Baseline** | 87.8% |
| **Thresholds** | Green ≥ 92% · Amber 88–92% · Red < 88% |
| **Owner** | VP of Supply Chain |
| **Decision** | 1 – Reorder, 3 – Expedite |

## SVC-02 Order Fill Rate

| | |
|---|---|
| **Definition** | Percentage of customer orders where *every* line was filled from stock. Reflects the customer's experience: one missing part can stop a repair job. |
| **Formula** | Count of sales orders with all lines filled from stock ÷ count of sales orders |
| **Grain** | Sales order |
| **Source** | `demand_transactions`: `sales_order_id`, `qty_demanded`, `qty_filled_from_stock` |
| **Direction** | Higher is better |
| **Baseline** | 82.5% |
| **Thresholds** | Green ≥ 88% · Amber 82–88% · Red < 82% |
| **Owner** | Branch Operations Manager |
| **Decision** | 1 – Reorder, 3 – Expedite |

## SVC-03 Unit Fill Rate

| | |
|---|---|
| **Definition** | Percentage of units demanded that were shipped from stock immediately. Less strict than line fill; useful for high-volume parts like filters and fluids. |
| **Formula** | Σ `qty_filled_from_stock` ÷ Σ `qty_demanded` |
| **Grain** | Demand line |
| **Source** | `demand_transactions` |
| **Direction** | Higher is better |
| **Baseline** | 92.7% |
| **Thresholds** | Green ≥ 95% · Amber 92–95% · Red < 92% |
| **Owner** | Inventory Planning Manager |
| **Decision** | 1 – Reorder |

## SVC-04 Lost Sales Value

| | |
|---|---|
| **Definition** | Revenue lost because a part was not in stock and the customer bought elsewhere. The most direct financial cost of a stockout. |
| **Formula** | Σ (`qty_lost_sale` × `unit_price_usd`) |
| **Grain** | Demand line |
| **Source** | `demand_transactions.qty_lost_sale` joined to `sales_orders.unit_price_usd` on sales order + line |
| **Direction** | Lower is better |
| **Baseline** | $479K (1.7% of revenue) |
| **Thresholds** | Green < 1% of revenue · Amber 1–2% · Red > 2% |
| **Owner** | VP of Supply Chain |
| **Decision** | 1 – Reorder, 7 – Leadership focus |

## SVC-05 Average Backorder Age

| | |
|---|---|
| **Definition** | Average number of days customers wait for backordered parts. |
| **Formula** | Average of (`last_fill_date` − `demand_date`) for lines with `qty_backordered > 0`; open backorders use the report date |
| **Grain** | Demand line |
| **Source** | `demand_transactions` |
| **Direction** | Lower is better |
| **Baseline** | 5.0 days |
| **Thresholds** | Green ≤ 3 · Amber 3–7 · Red > 7 days |
| **Owner** | Branch Operations Manager |
| **Decision** | 3 – Expedite |

## SVC-06 Stockout Rate

|---|---|
| **Definition** | Percentage of stocked part–branch combinations with zero on hand at period end. |

| **Grain** | Branch × part, point in time |

# Inventory KPIs

These KPIs measure whether inventory investment is the right size and in the right place.

## INV-01 Inventory Value on Hand

| | |
|---|---|
| **Definition** | Total value of parts on the shelf. |
| **Formula** | Σ (on-hand qty × current `unit_cost_usd`) |
| **Grain** | Branch × part, point in time |
| **Source** | `inventory_transactions.balance_after`, `part_master.unit_cost_usd` |
| **Direction** | Neutral – measured against the inventory plan |
| **Baseline** | $17.9M |
| **Owner** | VP of Supply Chain |
| **Decision** | 5 – Excess, 7 – Leadership focus |

## INV-02 Inventory Turns

| | |
|---|---|
| **Definition** | How many times inventory is sold and replaced per year. The headline measure of inventory efficiency. |
| **Formula** | T12M cost of goods issued ÷ average month-end inventory value over the same 12 months |
| **Grain** | Branch × part category, monthly |
| **Source** | `inventory_transactions` (`txn_type` = Goods Issue / Goods Issue – Backorder; `qty` × `unit_cost_usd`) |
| **Direction** | Higher is better |
| **Baseline** | 1.1× (cost of goods $20.3M ÷ inventory $17.9M) |
| **Thresholds** | Green ≥ 3.0× · Amber 2.0–3.0× · Red < 2.0× |
| **Owner** | VP of Supply Chain |
| **Decision** | 5 – Excess |

## INV-03 Days of Supply

| | |
|---|---|
| **Definition** | How many days current stock will last at the expected demand rate. Answers *"how long will current inventory last?"* |
| **Formula** | On-hand qty ÷ average daily demand. Average daily demand = trailing 90-day demand ÷ 90, replaced by the forecast once available (Phase 4) |
| **Grain** | Branch × part, point in time |
| **Source** | `inventory_transactions.balance_after`, `demand_transactions.qty_demanded` |
| **Direction** | Within the target range |
| **Baseline** | 166 days (median, parts with demand) |
| **Thresholds** | Green 30–90 · Amber 15–30 or 90–180 · Red < 15 or > 180 days. Category ranges from `Inventory_Policy_Matrix` (min / max days of supply) override these |
| **Owner** | Inventory Planning Manager |
| **Decision** | 1 – Reorder, 5 – Excess |

## INV-04 Excess Inventory Value

| | |
|---|---|
| **Definition** | Value of stock above the planned maximum. |
| **Formula** | Σ max(0, on-hand − `max_qty`) × unit cost. Parts without a safety stock target use on-hand above 180 days of supply |
| **Grain** | Branch × part, point in time |
| **Source** | `inventory_transactions`, `business_files/safety_stock_targets.max_qty`, `part_master.unit_cost_usd` |
| **Direction** | Lower is better |
| **Baseline** | $216K for parts with targets (1.2% of inventory). Parts without targets are not yet included |
| **Thresholds** | Green < 5% · Amber 5–10% · Red > 10% of inventory value |
| **Owner** | Inventory Planning Manager |
| **Decision** | 2 – Transfer, 5 – Excess |

## INV-05 Non-Moving Inventory

| | |
|---|---|
| **Definition** | Share of inventory value with no customer demand in the last 12 months. Candidates for return to supplier, transfer, or write-down. |
| **Formula** | Value of branch × part with zero demand in T12M ÷ total inventory value |
| **Grain** | Branch × part, point in time |
| **Source** | `inventory_transactions`, `demand_transactions` |
| **Direction** | Lower is better |
| **Baseline** | 39% ($7.1M) |
| **Thresholds** | Green < 10% · Amber 10–20% · Red > 20% |
| **Owner** | VP of Supply Chain |
| **Decision** | 5 – Excess |

## INV-06 Stock at Risk

| | |
|---|---|
| **Definition** | Stocked parts projected to run out before the next replenishment can arrive. The early-warning list for planners. |
| **Formula** | Count of branch × part where (on-hand + open PO qty due within lead time + inbound transfers) < forecast demand over supplier lead time ÷ count of stocked branch × part |
| **Grain** | Branch × part, daily |
| **Source** | `inventory_transactions`, `purchase_orders` (open), forecast, `supplier_master.lead_time_days` |
| **Direction** | Lower is better |
| **Baseline** | Calculated in Phase 4 (needs the forecast) |
| **Thresholds** | Green ≤ 2% · Amber 2–5% · Red > 5%; any critical part at risk is Red |
| **Owner** | Inventory Planning Manager |
| **Decision** | 1 – Reorder, 3 – Expedite |

## INV-07 Inventory Record Accuracy

| | |
|---|---|
| **Definition** | Percentage of cycle-counted part locations where the system quantity matched the physical count. |
| **Formula** | Count of cycle counts with no adjustment ÷ count of cycle counts |
| **Grain** | Branch × part × count date |

# What The Baseline Tells Us

The baseline already points to where the platform can add the most value:

- **Inventory is heavy for the service it delivers.** Turns of 1.1× and 39% non-moving value, against typical dealer targets of 3× or more, while line fill rate is still below 92%. The network holds a lot of stock, but not always of the right parts in the right branches. This is the core case for Decisions 2 and 5.
- **Supplier reliability is a lead-time problem, not a quality problem.** On-time delivery is 85% with a 6-day standard deviation, but only 0.14% of units are rejected. Planning parameters (master lead times, safety stock) need to reflect actual supplier behavior.
- **Transfers are underused.** Only 5.6% of replenishment comes from other branches, despite excess stock in the network.

These baselines will be recalculated from the curated data model in Phase 3, after data quality rules are applied.
